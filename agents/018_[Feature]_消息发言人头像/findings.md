# Findings

- 现有 `avatarRetryStates` 按头像路径缓存，`avatarSource`、`avatarKey`、`imageLoaded`、`imageFailed` 可复用于消息发言人头像。
- 消息快照的 `sameInbox` 比较尚未包含发言人头像路径；必须加入以接收后到的头像资料。
- 线程头像由 `.message-row` 采用 flex 布局，可添加固定宽度小头像；移动端正文区域需保持 `min-width: 0`。
- 根仓库当前 UI 测试已覆盖图片成功/失败与占位数量；新 fixture 可延续这些断言并增加多发言人头像与无头像情况。
- 消息行始终渲染发言人姓名首字占位；只有 `senderAvatarPath` 有值时才插入图片，避免用会话头像推断发言人身份。
- 头像缓存清理活跃集合包含当前消息的发言人头像路径，因此后到头像可以重试，并在消息离开当前快照后清理。
- 测试用刷新响应把发言人头像从 v1 更新到 v2，以验证仅头像路径变化也会导致快照更新；两种方向、无头像、成功/失败图片占位均通过。
