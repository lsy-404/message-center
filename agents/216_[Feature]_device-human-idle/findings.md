# Findings

- Activity state is version 4 and is accepted on restart only when it is a bounded regular non-symlink file with the complete typed schema.
- Missing, malformed, oversized, stale, or invalid state fails closed and requires the 180-second safety grace plus cleanup.
- Only an exact FileNotFoundError is treated as a first-run missing state; symlinks (including dangling links), non-regular files, and lookup/read errors preserve cleanup-required fail-closed behavior.
- A strict healthy/idle state with cleanupRequired false can restart through safety grace without consuming app-card cleanup budget.
- Actual physical HOME/touch and SpringBoard cleanup validation remain parent-owned.
- The checked-in classifier sees only callback-root events: type 11 immediately updates digitizer activity; type 3 is read for the verified consumer HOME usage/down fields. Apple OSS `HIDEvent.m` wraps `IOHIDEventGetChildren(IOHIDEventRef)` as `(__bridge NSArray *)`, establishing the user-space NSArray/CFArray object contract and borrowed (non-transfer) ownership for the returned reference. It does not prove this iPad's IOKit exports the symbol; the diagnostic resolves it with `dlsym` and refuses to run if unavailable.
- A live snapshot with HOME sequence 1 and digitizer sequence 0 confirms HOME classification only. It does not establish whether touch reports were absent, wrapped in a root event, or missed by event delivery; no lastActivityAt timing sample was provided to determine the resume deadline.
- ActivityPolicy starts its 180-second timer when the monitor is ready, resets lastActivityAt on each classified HOME/digitizer callback, and clears armed only after the monotonic elapsed interval reaches 180 seconds. Later callbacks while cleanupRequired is already true stay in memory and the monitor persists them on its two-second heartbeat; no per-input timestamp history is kept.
- The owned diagnostic aggregates fixed callback-root and child event-type counters under strict event-tree and duration caps; it emits no coordinates, keyboard usage/value fields, text, raw event dumps, or per-event logs. The parent must confirm the target export and compare counts during an explicit touch window, alongside monitor health and lastActivityAt.
# HID child traversal evidence and probe boundary

Apple's IOHIDFamily user-space `HID/HIDEvent.m` implements `-children` by returning `(__bridge NSArray *)IOHIDEventGetChildren((__bridge IOHIDEventRef)self)`. This is direct primary Apple user-space evidence that the getter accepts an event reference and returns an NSArray-compatible object; the plain `__bridge` indicates no ownership transfer. Since NSArray and CFArray are toll-free bridged, the bounded diagnostic can type-check and read the borrowed result through CoreFoundation while the callback event remains alive. The exact C declaration is imported from Apple's private `IOKit/hid/IOHIDEventPrivate.h`; the open repository does not expose that header, so the diagnostic uses `dlsym` and a pointer-returning ABI matching the bridge expression, and fails closed if the export is absent. The target export still requires device verification.

Apple's CoreFoundation implementation establishes `CFArrayGetCount(CFArrayRef) -> CFIndex` and `CFArrayGetValueAtIndex(CFArrayRef, CFIndex) -> const void *`; the latter returns the bucket's item directly without retaining it. The probe validates the bridged array's runtime type before accessing it and keeps all borrowed references within the callback lifetime.

The top-level activity classifier currently only records digitizer activity for root type 11. Prior device counters (Home sequence 1, digitizer sequence 0) establish that Home was classified, but cannot establish whether the subsequent touch was absent, delivered in a non-digitizer root, wrapped in child events, or not delivered to this listener. The owned diagnostic probe now aggregates root and child event-type counts only. It caps the window at 300 seconds/25,000 callbacks; each event tree at 32 children per node, depth 4 and 64 total nodes; malformed or over-limit child trees increment an error counter and contribute no partial child counts. It publishes only fixed type counters and lifecycle/health aggregates once per second, with no coordinates, values, text, raw events, or per-event logs. No production event classification is changed. Root must verify the target export and run it during an explicit touch window before drawing conclusions; missing symbol or malformed bridge data fails the diagnostic closed. The target OS may differ from the current Apple OSS source revision, so runtime export verification remains necessary.

Timing remains uncertain: root reported a monotonic `lastActivityAt` and a later process uptime consistent with roughly two minutes from Home to that sample, but this does not identify the timestamp of the physical touch or prove that the digitizer counter failed to refresh. Collection may also remain paused due to the separate outbox condition root is investigating.
