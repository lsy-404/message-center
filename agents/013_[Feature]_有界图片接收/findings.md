# Findings

- Worker already provides `PUT /api/connectors/files/<fileId>` with connector authentication, SHA-256 and content-length validation, a 50 MiB limit, R2 storage, and idempotent reuse by connector plus external file ID.
- Normal `/api/connectors/events` accepts attachment metadata and binds uploaded inbound attachment rows to the message. The runtime must upload every image before posting the message, and retry the same stable external IDs if a response is lost.
- `group + background` events are suppressed by the ordinary event route. The existing group-text-backups POST preserves these messages outside agent_queue but rejects attachments; its POST path will be extended to link uploaded image metadata while retaining background queue class. The GET API remains unchanged.
- Private adapter contract: write a completed file atomically under the runtime-owned media directory and return `{externalId,fileName,mimeType,sizeBytes,sha256,stagingKey}`. The runtime accepts only safe single-component staging keys and image MIME types, verifies size/hash using bounded reads, and counts media bytes against the existing connector outbox ceiling.
- Scan input includes `mediaDirectory` and remaining connector bytes as `maxMediaBytes`. Staging defaults to `<database>.media`, resolved relative to config and mode 0700. File identifiers are stable across retries; the staging key is not sent to the Worker.
- The runtime streams file uploads in 64 KiB chunks. No image bytes enter the JSON outbox; bounded attachment metadata and the local staging key remain durable until Worker acceptance. The sample queue is 128 MiB overall, giving two connectors 64 MiB each for the existing 50 MiB Worker file limit plus event metadata.
- The existing group backup endpoint now validates prior uploads, stores attachment metadata on the normalized message, binds rows to that message, and leaves it in `background` without adding it to `agent_queue`. A missing upload, mismatch, or incomplete binding rejects the response, leaving the local outbox eligible for retry.
- Image-only group background messages use the fixed `[图片]` placeholder because the backup row requires nonempty text; image content stays in the R2 attachment object.
