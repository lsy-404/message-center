# Findings

- Human access currently accepts a password equal to ADMIN_TOKEN or that same token as a bearer credential. HMAC browser sessions also use ADMIN_TOKEN. Both entry paths must be removed rather than retained as alternate administrator access.
- The Worker protects application assets, inbox and administrative mutations through humanIdentity. Attachment downloads have their own identity checks and require explicit regression coverage.
- Device connector authentication and agent MCP authentication are separate machine contracts and are not interactive user sign-in. Preserve their existing scope and tokens.
- Public main is clean at c53a235 and matches origin/main after fetch. Production deployment identifiers remain in ignored local configuration; private adapters and user data must not enter this branch.
- Verified the actual provider issuer and discovery document. ID Token/UserInfo contain no role claim, but authenticated access-token introspection joins the live user row, checks enabled/revoked/expiry/client/app access, and returns roles:[admin] exactly for user level3. Administrator authorization must use that introspection result, not identity profile or email.
- App allow_all=false is separate from OAuth confidential-client authentication. Enforce both a private app policy at the provider and client_secret_basic for server-side token exchange; still require the live admin role in Message Center so an explicit ordinary-user assignment cannot grant data access.
- Provider access tokens expire after300s. Use the mature server-side session pattern with an opaque cookie, encrypted token storage and an atomic refresh lease so ordinary browsing does not force a full login every five minutes or race rotating refresh tokens. Add a new table to the current schema and provision only that table; do not retain old password sessions or write compatibility migrations.
- Existing production Message Center has only the legacy admin/agent/connector secrets. Requested the exact client_id and protected client-secret location, since Cloudflare secret listing cannot read existing plaintext. Implementation and offline validation can proceed independently.
