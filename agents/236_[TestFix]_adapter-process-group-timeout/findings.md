# Findings
- The production adapter launches POSIX helpers with start_new_session=True; its exception path sends SIGKILL to os.killpg(process.pid, ...), then waits on the helper. This is intended to terminate descendants sharing that process group.
- The failing test started a child that wrote after a fixed 0.8-second delay, invoked the adapter with a 0.25-second timeout, then waited and repeated the identical block. The timing did not prove the child had started before timeout, and the duplicate added no coverage.
- The replacement waits for child and parent readiness metadata, records both PIDs/PGIDs, and tests both a parent that exits while its child keeps stdout open and a parent that waits. In each case the test releases the child only after `run_adapter` returns, then verifies the marker is absent. On assertion failure it cleans up only recorded PIDs after confirming their process group.
- The POSIX branch of `run_adapter` already kills the helper's process group. This Windows host skips the POSIX-only behavior test; the Darwin test command is `python3 -m unittest test.test_device_runtime.DeviceRuntimeTests.test_adapter_deadline_bounds_large_input_oversized_output_and_closed_stdout` from the repository root.
