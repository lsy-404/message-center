## Candidate review

- `/api/inbox` projects `connector_kind` into `connectorKind` and returns `conversationType`, `placement`, and `unreadCount`; the candidate's classification uses the protocol field `connectorKind === 'qq'`, not a display label. This preserves custom QQ channel labels.
- The group-assistant predicate is strict: QQ + `conversationType === 'group'` + placement `folded` or `message_box`. It excludes normal QQ groups, direct QQ chats, unknown placements, and non-QQ groups.
- Search and unread filtering compose with that predicate, and the displayed list drives pagination, range/count labels, and visible rows. The QQ protocol filter is separately available; the “return to QQ” action selects it. Existing `FluentButton` and `FluentField` components are reused, and rendering remains page-limited through the existing 100-item page helper.
- The follow-up `b5f402509303763598161a07eabc5f9ee22384cb` fixes the direct empty-view leak by routing both view changes through `resolveConversationSelection()`, caching the prior composer before clearing, setting `activeFilter` to `protocol:qq`, and placing QQ before channel labels. The decision helper has a regression for keep/select/clear; these state transitions are consistent with the existing per-conversation draft cache.
- Remaining blocker after `b5f4025`: clearing selection is not stable across refresh. `createInboxRefreshLoop` calls `load(selectedId.value, true)` every five seconds; when the new empty view has `selectedId === ''`, `/api/inbox` omits `conversationId`. Worker `readInbox()` then falls back to its first conversation (`worker/index.js:1866`), and `load()` applies `body.selectedConversationId` back to the UI (`App.vue:714`). The QQ assistant view can therefore reacquire a nonmatching global conversation as the active thread/send target after an automatic or manual refresh. Keep the visible list refreshed while preserving a deliberately empty local selection for the empty scoped view, and cover the refresh path.
- The 17-item/page behavior uses the existing computed list and page helper (100 rows), so the new assistant view does not duplicate-render a second conversation list. Search and unread filters are applied before paging; the return action switches to the QQ protocol filter. The candidate reuses existing Fluent controls. No other concrete blocker was found in classification, custom labels, counts, paging, or draft caching.
- Validation on `d42e01a` and `b5f4025`: targeted Node tests passed 4/4 and 5/5 respectively; UI type check and production build passed on both snapshots. These checks do not exercise the five-second auto-refresh behavior, which is the remaining blocker. No browser, cloud write, or device operation was performed.
