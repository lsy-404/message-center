# Findings

`Relay.flush_one()` currently selects one oldest outbox row per connector, chooses `/api/connectors/events` or `/api/connectors/group-text-backups` from the row's group/background fields, and deletes that row only after a successful HTTP response. Attachments are uploaded before the event request and stripped of local staging keys for wire delivery.

The Worker events route accepts up to 100 messages and returns `{ok, received, inserted, upgraded, promoted, suppressed}`. Its `received` is the submitted array length; `suppressed` counts rejected-by-policy items. `inserted`, `upgraded`, and `promoted` can legitimately be lower or nonzero on dedupe/replay. A local Worker integration fixture now verifies a two-row first ingest returns `received=2, inserted=2`, and replay returns `received=2, inserted=0`, with the other counters zero. The group-backup route accepts up to 100 and returns `{ok, received, inserted, normalizedInserted, retentionDays}`; duplicates make insertion counts lower, while `received` is still submitted length. A local Worker integration fixture verifies both first ingest and replay over two rows, including `retentionDays=30`. The group route validates and inserts backups as a D1 batch, then normalizes rows; the response is returned only after normalization and summary reconciliation complete. Both routes are idempotent for same external IDs; a conflicting ID/body/conversation fails instead of acknowledging.

The device outbox stores compact serialized event bodies and their byte length per row. `MAX_EVENT` (256 KiB) applies per staged event; the Worker body parser caps one request at 2 MiB. A batch must also enforce a bounded aggregate request size. `MAX_DELIVERIES_PER_PASS` is five, and pending outbox rows block source scans for that connector; batching can reduce the time spent draining text backlog, but does not itself resolve source scheduling delays when other work or failures intervene.


The implementation caps a batch at 20 rows and `MAX_SCAN_RESPONSE` bytes of the exact serialized request, while preserving connector rotation after each successful batch. Prefix deletion compares every selected row's sequence, connector, profile, external ID, body, and stored size within one `BEGIN IMMEDIATE` transaction; any mismatch rolls back the batch deletion. Attachment rows still use the single-event upload path.
